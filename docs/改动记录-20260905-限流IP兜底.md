# 改动记录 · 限流 key 匿名回落 IP（2026-09-05）

> 关联：交接文档 v5 第 6/7 节红线（AI 端点限流）、边界测试 R11（rename 被刷账单）、
> 本轮代码审计发现（匿名限流 key 可旋转）。

## 背景

R11 给 rename 挂上限流修的是"漏挂"，没修"挂了也白挂"：限流 key 对匿名用户取
`user:web_<X-Device-Id>`，而该身份来自**客户端自报的 header**，可任意伪造/旋转——
换一个 header 即新额度，所有 `L_TUTOR/L_UPLOAD/L_HEAVY` 端点对匿名流量形同虚设。

本产品定位"不收费、搜集用户与 AI 对话数据"，限流因此有双重意义：
成本防线（AI 账单/单机 CPU）+ **数据质量防线**（脚本刷入的垃圾对话污染语料）。

## 改动内容

1. `backend/rate_limit.py::_key_func`
   - 真实登录用户（openid 非 `web_` 前缀）→ 仍按 `user:<openid>` 记账
   - 匿名 `web_*`（含 web_anon）→ 一律 `ip:<client_host>` 记账
2. `backend/tests/test_rate_limit.py`
   - 新增回归锁 `test_key_func_anon_device_falls_back_to_ip`

## 前置条件（部署前实测确认）

- nginx `/etc/nginx/sites-available/moyan`：已配 `X-Real-IP` +
  `X-Forwarded-For $proxy_add_x_forwarded_for` ✅
- systemd `moyan.service`：uvicorn 带 `--proxy-headers --forwarded-allow-ips=*`，
  且仅绑 127.0.0.1（外部无法绕过 nginx 伪造头）✅

## 验证

- 生产部署后：35 次匿名请求打到 `/api/tutor/start` → 预期尾部 429
  （仅消耗 `ip:127.0.0.1` 桶，不影响真实用户）

2. `systemctl restart moyan`（约 3 秒中断；进行中的 SSE 会掉线，前端重试即可）
3. `systemctl is-active` + `/api/health` 200 + 匿名 429 实弹验证
4. 回滚：`git show 4f72eea:backend/rate_limit.py > 旧版` 重传 + 重启

## 行为变化（接手团队必读）

- 同一出口 IP（家庭/办公室 NAT、校园网）下的多个匿名用户**共享**
  30/min 教学、5/h 上传额度——这是有意的取舍。
- 微信登录用户不受影响，仍按个人 openid 记账。
- 若某 IP 段合法用户密集导致误伤，应为 `ip:` 维度单独放宽档位，
  **不要**退回 `web_*` 记账。

## 本改动之外、本轮新发现的边界（新增待办）

1. **`/api/tutor/turn` 不校验会话归属**：只查会话存在，未比对 owner 与请求者。
   `session_id = "s_" + uuid4().hex[:10]`（40 bit 熵），限流修好后爆破不现实，
   但"持有即授权"是设计缺口。建议：load 后比对 openid，不一致返 404。
2. **AI 生成无 max_tokens 上限**：`providers.py` 支持该参数但全链未传，
   "把整本书讲一遍"类 prompt 可触发超长计费生成。建议 settings 参数化 + 分动作默认值。
3. **同会话无并发锁**：双开/重试风暴可对同一 session 并发 `handle_turn`，
   状态机存在竞态。建议 per-session in-flight 锁，冲突返 409。
4. **全局预算熔断**：ai_usage 按日累计，超阈值自动降级 cheap 引擎或 429。
   IPv6 仍可旋转，IP 限流非万能——这是免费产品最后的保险丝。
5. **对话数据搜集的 PIPL 合规**：隐私告知 + 保留期限策略。
