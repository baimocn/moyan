# 墨衍 · 全类型文档转 Markdown 项目调研 + Docling 实测（2026-08-28）

> 决策要求：GitHub 上找"所有类型文档 → MD"最优项目，**质量 70% / 速度 30%**。
> 一手信息来自 GitHub 各仓库主页 README（浏览器实抓），实测在本机 Windows + CPU。

**结论**：主引擎选 **Docling**；PDF 扫描/复杂页的上限兜底用 **MinerU**（或已实测的 PP-Structure）；
RapidOCR/文本层保留为快速校验。

## 二、Docling 2.123.0 本机实测（.docling-venv，CPU，Python 3.13）

样本：《普通生物学》真实扫描页（150dpi）+ 生成的 PPT 课件（中文表格/要点/公式行）。

| 样本 | Docling 耗时 | 质量观察 |
|---|---|---|
| p0377（遗传病正文页） | **13.9s** | `## 1.缺失 / ## 2.重复 / ## 3.倒位` 标题层级、阅读序、图片占位符、图注正确 |
| p0134（肾脏行流页） | **37.9s**（含模型权重加载） | md 1918 字符，出现表格行（13 行 `|`） |
| p0343（染色体数表） | ≈同量级 | **转为 Markdown 表格**，数值正确（猪38/猫38/兔44/鼠40…） |
| PPT 课件 | **≈0.0s** | **完美**：标题/要点（- 前缀）/中文表格全转 MD 表格，零损耗 |

**对比基线**（同页同机）：
- PP-StructureV3：88~183s/页（质量上限高：表格 HTML+公式 LaTeX+版面分区）
- RapidOCR：2.7~4.1s/页（纯文本，无结构）

**Docling 定位**：速度约 PP-Structure 的 1/5~1/10，质量覆盖"表格/版面/阅读序/扫描 OCR"，
对 2G/2核 服务器是**唯一可能整本跑得动的高质量全类型方案**（仍需全本实测）。

## 三、坑（别人会再踩）

1. docling 需 Python ≥3.10；system 是 3.14 → 用 `.docling-venv`（py3.13）
2. 首次转换需下载模型（HF）；国内网络不通时设 `HF_ENDPOINT=https://hf-mirror.com`
3. 影像页会出 `<!-- image -->` 占位（需后续多模态/OCR 图片内文字）
4. 双栏并排子表可能被合并成一张 4 列表（数据对、列序需人工核）

## 四、对墨衍的落地（建议，待拍板）

```
上传 → Docling（主引擎，全类型→MD）
      → 扫描/公式极限页：MinerU 或 PP-Structure（按页抢救，离线/按需）
      → 保留 RapidOCR/文本层作快速校验
```

- PPT 接入不再是问题：Docling 直读 pptx → MD（0s，表格无损）——替代此前"python-pptx 自写 parser"的设想
- 章节策略 A(Sections)→B(大标题页)→C(单章) 在 Docling 之上依然适用（输出 MD 后走现有切章）
- 2G 服务器整本 PDF 的 Docling 全量耗时需实测（本机单页 14~38s，466 页约 2~5h 观望）
