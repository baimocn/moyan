## 一、验收路径

`POST /api/tutor/start`（《操作系统》教材 ch0）→ `/api/tutor/turn` 讲解（SSE 流式）
→ 提问 → 学生作答"答案选 A，进程就是一个程序文件" → 判定 → 分支 → 巩固题/重讲。

## 二、结论：核心"像老师"成立 ✅

- **讲解**：单点（操作系统定义）、一个类比（餐厅总经理）、直引教材（"教材里说得很直白"）、
  **以问题结尾**（"操作系统的主要作用是什么？一句话说说"）——命中 8 硬规则（一次一概念/不罗列/以问收尾/只依据教材）。
- **提问**：single_choice，4 选项，干扰项对应真实常见误区（硬件设备/办公软件/编程语言），easy→medium 阶梯。
- **判定反馈**：苏格拉底式——先肯定 → 点出误区（"进程和程序文件不是一回事"）→ 阶梯提示，
  **不给完整答案**；weak_points（os/definition、process/definition）与知识点标签同体系。
- **token 真实记账**：讲解流 906/153（prompt/completion）落库。

## 三、发现并已修复的问题

| # | 问题（真机实录证据） | 修复 |
|---|---|---|
| 1 | **答案泄漏（支架崩塌变体）**：判定反馈直接说"你选对了答案 A"，且下一题正确项恰好仍是 A → 学生复选即可通关 | ① 反馈程序级过滤（`_sanitize_feedback`：剥选项字母与正确项文字，保留引导）；② **选项洗牌** `shuffle_options`（正确项位置每次随机，测试保证映射一致）——双保险 |
| 2 | **性能**：章计划生成 79.5s（LLM 一次约 80s）| **章计划缓存** `storage.save/load_learning_plan`：每章只生成一次，复验 start 0.0s |
| 3 | 判定 65s（疑似 instructor 重试叠加）| 记录留档；后续可降 `max_retries` 或改调用方式（未在此轮处置） |
| 4 | question_id 被 LLM 自拟覆盖（"os/intro/definition/01"），破坏审计关联 | `make_question` 强制采用调用方 question_id |

复验（同教材、同样的错误回答）：start 0.0s；feedback 全文正则 `\b[A-F]\b` 零命中；
讲解文本中的教材定义属教学内容（非答案标记），正常保留。
