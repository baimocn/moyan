# Plan 01-01 — 权限分层与生产安全硬校验

对应需求：ADMIN-01、ADMIN-02（机制部分，应用点在 Phase 2 DELETE）、ADMIN-03
对应路线图 Phase 1 成功标准 1/2/3/4。

## Tasks

### T1 配置层：env 与管理员清单
- 文件：`backend/settings.py`
- AppSettings 加 `env: str = "dev"`（MOYAN_ENV，production=生产）与 `admin_openids: str = ""`
- 加 property `admin_set -> frozenset`（逗号/空白拆分去空）
- 验收：admin_set 空清单/多值/带空格均正确

### T2 身份层：role 贯通
- 文件：`backend/auth/deps.py`
- `CurrentUser` 加 `role: str = "anon"`；新增 `_role_for(openid)`：openid ∈ admin_set → "admin"，否则 "user"
- `get_current_user` / `get_current_user_optional` / `get_requester` 三处赋 role：Bearer 分支用 `_role_for`；设备分支固定 "anon"；mock 分支固定 "admin"（dev 便利）
- 新增依赖 `require_admin(user=Depends(get_requester))`：role != "admin" → HTTPException 403 "需要管理员权限"
- 验收：单元级 + 挂临时路由的 API 级测试（admin 200 / user 403 / anon 403）

### T3 生产安全硬校验
- 文件：`backend/settings.py`（纯函数）+ `backend/main.py`（lifespan 调用）+ `backend/auth/router.py`（dev-login）
- 新增 `apply_production_safety()`：env=="production" 且 auth_disabled → 强制 False + logging.warning
- dev-login：env=="production" → 403（双保险，即便有人手动改回）
- 验收：monkeypatch env=production + auth_disabled=True → 调用后 auth_disabled 为 False；dev-login 403

### T4 /me 暴露 role
- 文件：`backend/auth/schemas.py`（MeResp 加 `role: str = "user"`）、`backend/auth/router.py`（me 两处返回带 role）
- 验收：admin token 调 /me 返 role=admin；普通返 user

### T5 测试与回归
- 新文件：`backend/tests/test_admin_roles.py`（覆盖 T1-T4 全部验收点，monkeypatch 显式控制 app_settings，不用模块级 setdefault）
- 全量 pytest 回归 + `git diff --name-only` 确认仅 backend/ 变更

## Deviations（规划期修正）

- ADMIN-02 的 403 应用对象原写"文档 DELETE 等破坏性写操作"；研究确认 rename 是普通用户日常功能不可收权，DELETE 在 Phase 2 才诞生。本计划交付 require_admin 机制 + API 级行为测试（测试内挂临时路由验证），真实端点挂载归 Phase 2。
