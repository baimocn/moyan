## 二、深度拆解（6 个代表项目）

### 2.1 Mr. Ranedeer AI Tutor（29,597★）——提示词工程的巅峰之作

**教学法落地**：它不是 App，而是一份 5,376+ token 的系统提示词（v2.7 `Mr_Ranedeer.txt`），把"老师"定义成可配置人格 + 显式教学状态机：

- **学生配置项**：`🎯Depth`（小学→博士 10 档）、`🧠Learning-Style`（Visual/Verbal/Active…）、`🗣️Communication-Style`（**Formal/Textbook/Layman/Story Telling/Socratic**——苏格拉底是五种沟通风格之一）、`🌟Tone-Style`、`🔎Reasoning-Framework`（Deductive/Inductive/Abductive/Analogical/Causal）。
- **命令即课程状态机**：`/plan`（生成课程大纲）→ `/start`（开始上课）→ `/test`（测验）→ `/continue`（续讲）→ `/config`（改配置）。大纲分**先修课 0.1–0.9** 和**主课 1.1–1.10** 两段编号，直接对应"墨衍：从第 X 章开始讲解"的路径概念。
- **提问后必须停住**（原文逐字）：
  ```
  [IF tutor asks a question to the student]
      <stop your response>
      <wait for student response>
  ```
  教学 Loop 每一轮：讲课 → 问一个问题 → **立即停止输出等学生**；学生答完再进入下一轮——这是"系统主导、单问题交互"的范例。
- **/test 三级难度出题**（原文逐字）：
  ```
  <generate simple familiar problem, the difficulty is 3/10>
  <generate complex familiar problem, the difficulty is 6/10>
  <generate complex unfamiliar problem, the difficulty is 9/10>
  ```
  先给"示例题 + 逐步解答"，确认学生看懂后才开始考；每道题后 `<stop your response>`。
- **隐藏思考**：趁上课间隙在"代码环境"里用注释写"基于学生配置该怎么教、学生学得怎么样"，然后 base64 输出、明令"不展示给学生"——相当于最早的 CoT+教师决策日志。

**启示**：提示词即可承载完整的"讲解→提问→等答→测验→按答况调整"循环；不用上复杂 agent 框架也能做，但**上下文里必须持久化"当前章节编号 + 学生配置 + 课程大纲"**。

### 2.2 EduChat（华东师大，966★）——中文教育大模型，公开苏格拉底系统提示词

EduChat 的 README 直接贴出了生产级系统提示词 `PROMPT_TEMPLATES`，其中"引导式教学"模板是市面上最清晰的苏格拉底落地方案（逐字）：

```
# 引导式教学主题的要求：
EduChat 你需要扮演一位精通苏格拉底教学法的教师，核心使命是通过**系统性提问**
引导学生自主发现知识。请遵守以下原则：
# 1. **绝不直接给出答案**：用问题拆解复杂概念，引导学生逐步推导结论。
# 2. **针对性追问**：根据学生当前回答的认知漏洞设计下一层问题。
# 3. **知识脚手架**：问题难度呈阶梯式上升（从具体→抽象，已知→未知）。
# 4. **辩证批判**：当学生给出片面结论时，提出反例或逻辑悖论引发反思。
# 5. **鼓励元认知**：在关键节点提问"你如何验证这个观点？"、"之前的推理是否有矛盾？"
```

配套还有**开关式路由**系统提示词（`<|system|>` 里 `Socrates: Enable/Disable` 切换教学/心理/通用主题），以及"情感支持"模板（复合 EFT/CBT/情绪 ABC + 苏格拉底提问）。

EduChat-R1（Qwen3 8B/32B）主打 **"Thinking before teaching"**：先让模型推理"教什么/怎么教/学生状态"，再输出教学方案，支持 MCP 工具调用——这正是"教学引擎先规划后讲解"的架构背书。

**启示**：①苏格拉底约束可以直接写进 system prompt 的五条原则，中文产品可原样借鉴；②教学与心理疏导要分流（答错挫败感需要情绪支持模块）；③"先思考再教"的规划步骤（lesson planning）值得做成墨衍的独立管线。

### 2.3 OATutor（UC Berkeley，245★）——把"薄弱点记忆"做成算法

OATutor 是老牌 ITS 的现代开源版，教学法不靠 prompt 靠**模型**：

- **贝叶斯知识追踪（BKT）**：每个知识点（KC）有 `probMastery / probTransit / probSlip / probGuess` 参数，学生每答一题就更新掌握度（`BKT-brain.js` 实现标准更新公式）。
- **最低掌握度优先选题**（README 原文）：
  > "heuristic that selects problems prioritizing the lowest mastery first… 计算每个 problem 的掌握度（把一个 step 所有 KC 的 mastery 相乘），选最低的给学生。"
  即：**薄弱点驱动下一题选择**，不是给学生自由选课。
- **分级提示（hint pathway）**：
  > "hints 是纯文本、无输入；scaffolds 包含用户输入（文本框或多选），且 scaffolds 内部还能嵌帮助；最后一层是 bottom-out hint（含答案的保底提示）。"
  配套配置开关：`giveHintOnIncorrect`（答错自动进入提示路径）、`unlockFirstHint`、`allowDynamicHint`（LLM 动态生成提示）、`giveStuBottomHint`、`enableCompletionMode`（**达到掌握阈值才结束本课**）。
- **答案判定器**：`checkAnswer.js` 支持 Algebraic（代数化简相等）/ String（精确匹配）/ Numeric（数值等价）三种确定性判题——数理题不靠 LLM 判对错。
- **AB 实验**：BKT 参数、HintPathway、选题启发式都可配置多套做 AB（其 PLOS ONE 2024 论文报告了学习增益与 **LLM 生成提示**的效果）。

**启示**：墨衍的"记录薄弱点"应落到**知识点粒度 + 概率掌握度**（BKT 或简化版），并用"最低掌握优先"算法自动选题；判题分两条线——确定性题（公式/数值/字符串）用代码校验，开放题才交给 LLM。

### 2.4 OpenTutor（86★）——与墨衍最像的"上传教材→自适应导师"

README 首页即产品愿景："Drop in a PDF. Get an AI tutor that actually adapts to how *you* learn."，主循环：

```
Upload → AI Teaches → You Practice → AI Remembers → AI Reminds → Repeat
```

- **30 秒内容摄入**：上传 PDF/DOCX/PPTX → 自动生成结构化笔记、闪卡、测验（7 种题型：单选/简答/填空/判断/配对/排序/编程）。
- **3 个专职 Agent**（意图路由编排）：Tutor（自适应深度 + **苏格拉底提问模式** + 引用教材来源）、Planner（学习计划/目标/截止日）、Layout（按活动调整工作区布局）。
- **教学法 = 学习科学栈**：
  - FSRS 4.5 间隔重复（记不住的自动提醒复习）；
  - **LOOM 知识图谱**："追踪概念掌握度、先修关系、薄弱点"，基于概念图生成最优学习路径（arXiv 2511.21037）；
  - LECTOR：知识图谱感知的复习优先级（先修优先于后继）；
  - **认知负荷理论**：12 个行为信号（疲劳检测、错误模式、消息长度等）实时调整讲解难度。
- **技术实现**：FastAPI + Next.js 16 + SQLite；混合 BM25+向量 RAG；**10+ LLM 供应商 + 熔断器路由**（Ollama/OpenAI/Anthropic/DeepSeek/Gemini/vLLM/OpenRouter 任一 OpenAI 兼容端点）。
- 导师回答全部**带教材来源引用**。

**启示**：墨衍的"上传资料→分章节→讲解→考→记薄弱点"闭环在这里有完整开源实现可抄作业；技术栈（FastAPI + 多供应商 OpenAI 兼容层）与墨衍方案同构。

### 2.5 DeepTutor（HKUDS，37,635★）——记忆即教学资产

HKUDS（LightRAG 同团队）的 agent 原生学习工作区，2025-12 发布、39 天破 10k star，教学相关的三个核心设计：

- **三层可审计记忆（L1/L2/L3）**（README 原文）：
  > "Memory is a file-backed, three-layer system you can read, curate, and audit — **deliberately not a hidden vector store**. L1 is the append-only event trace (`trace/<surface>/<date>.jsonl`); L2 is per-surface curated facts (`L2/<surface>.md`); L3 is cross-surface synthesis (`L3/<profile|recent|scope|preferences>.md`). Because L2 cites L1 and L3 cites L2, nothing in your profile is unaccountable."
  Memory Graph 把 L3 综合结论可回溯到 L1 原始事件——**每个"薄弱点"都有证据链**。
- **硬掌握门槛（hard mastery gate）**：Guided Learning 建在聊天 agent loop 上，"with a hard per-type mastery gate and a `/learning` dashboard"；Mastery Path 的"答对才过关"题目会回流到 Question Bank。
- **Book 引擎**：章节编译成类型化块（正文/提示框/测验/闪卡/时间线/代码/互动 HTML/概念图/深潜/笔记），"visited pages, bookmarks, and quiz attempts roll up into a **completion score and weak chapters**"。
- 统一 agent loop 承载 Chat/Quiz/Research/Solve/Mastery Path 等所有模式；多引擎 RAG（LlamaIndex/GraphRAG/LightRAG/PageIndex）；EduHub 技能市场甚至提供现成 `socratic-tutor` 技能（`deeptutor skill install socratic-tutor`）；论文 arXiv:2604.26962。

**启示**：墨衍的 PostgreSQL 里应有**等价于 L1 的事件表（每次问答/对错/耗时）**与**等价于 L2 的知识点掌握度表（可审计、可人工修正）**；"章节未达标不推进"用 mastery gate 实现；每次讲解的引用要可回溯到教材原文。

### 2.6 MathTutorBench（ETH，43★，EMNLP 2025 Oral）——把"会教书"变成可评测的任务集

一个**导师能力评测基准**，定义了 LLM 导师应具备的 3 大教师技能、7 个具体任务（每个任务配了教师人工标注的 ground-truth，用 1.5B 教学奖励模型算 win-rate）：

| 高维技能 | 评测任务 |
|---------|---------|
| Math Expertise | problem_solving（解题）、**socratic_questioning（苏格拉底提问）** |
| Student Understanding | student_solution_correctness（判断学生解法对错）、**mistake_location（定位错误）**、**mistake_correction（纠正错误）** |
| Pedagogy | **scaffolding_generation（生成脚手架提示）**、**pedagogy_following（遵循教学原则）**（各有 hard 变体） |

**关键实证发现**（README leaderboard）：
- "**strong problem solvers are not automatically strong tutors**"：所有模型在 Socratic Questioning 上得分极低（GPT-4o 最高仅 0.48，绝大多数模型 ≈0.3）——LLM 天生"爱给答案"；
- 纯数学调优的模型（Qwen2.5-Math-7B）Scaffolding/Pedagogy win-rate 仅 0.05–0.07，**解题越强 ≠ 教学越强**；
- 评测走任一 OpenAI 兼容 API（`completion_api`，vLLM/OpenRouter 均可）——墨衍可直接用它给"导师引擎"做回归测试。

**启示**：墨衍应建立自己的"导师能力评测集"（苏格拉底提问/错误定位/错误纠正/脚手架/原则遵循至少 5 维），每次改 prompt 或换模型（GPT↔Claude↔DeepSeek）都跑一遍，用得分决定默认模型路由。

## 三、LLM 导师教学效果实测研究（2 篇主研究 + 4 篇补充）

### 3.1 主研究 ①：Tutor CoPilot（斯坦福，随机对照实验）——引用链接见文末

- 规模：**900 名导师 + 1,800 名 K-12 学生**，人类-AI 协作（给真人导师实时推送"专家式教学提示"），首个真人实时辅导场景的预注册 RCT。
- 结果：学生主题掌握率 **+4 个百分点（p<0.01）**；**低水平导师的学生提升达 +9 个百分点**；成本仅 **$20/导师/年**。
- 机制分析：用分类器分析 55 万+ 条消息，有 CoPilot 的导师**更常使用"引导性问题"等高质量策略、更少直接给答案**。
- 对墨衍的价值：**"不给答案、多提问"是可以被工程手段显著放大的**（即使是对真人导师），是苏格拉底教学法有效性的直接证据。

### 3.2 主研究 ②：LearnLM + Eedi 英国课堂 RCT（Google DeepMind）——引用链接见文末

- 规模：165 名学生、5 所英国中学；LearnLM（为教学微调的生成模型）接入 Eedi 数学平台聊天辅导。
- 结果：专家导师对 LearnLM 草拟消息的通过率为 **76.4%（零改动或仅改 1-2 字符）**；LearnLM 组学生在**后续新主题（novel problems）上的解题成功率 66.2% vs 真人导师组 60.7%（+5.5 p.p.）**，其余指标不差于真人。
- 亮点：访谈中导师盛赞 LearnLM **"起草的苏格拉底式提问能激发学生更深反思"**，多位导师表示从模型身上学到了新教法。
- 对墨衍的价值：用"新题迁移成功率"评测（而不是只考原题）是检验是否真学会的关键指标；模型侧"教学适配优于通用模型"是可复制的路线（prompt 级或微调级）。

### 3.3 补充研究要点

- **HeuristicEdu"超越直接作答"**（arXiv 2607.22996）：Qwen2.5-7B 用 SFT+GRPO 对齐苏格拉底行为，奖励 = 认知深度 R_cog + 好奇心参与 R_eng + 直接度 R_dir；效果：脚手架有效性 SE 30.0%→63.3%，**关键词泄漏（直接剧透答案）30.0%→13.3%**；未对齐的 Qwen-72B 基线 SE=0%、泄漏 96.7%——**模型规模大 ≠ 会自动苏格拉底教学，必须显式对齐**。
- **Khan 学院 CoMTA 论文**（仓库内 PDF）：Khanmigo 实测发现模型"有时给学生错误的对错判定"；188 段对话基准评估显示，**各模型"识别学生正确"明显好于"纠正学生错误"**（gpt-4o：85.8% vs 68.5%）——纠错是导师引擎最弱、最需要加强的环节；论文同时给出挑战分类学（学生要答案 / 反复答错 / 语言歧义 / 错误粘滞 / 轻信学生断言…）。
- **tutorbot（UMass，AIED'25）**：用"LLM 学生模型（LLMKT）预测学生答对概率 + GPT-4o 教学 rubric"给候选导师话语打分，再对 Llama 3.1 8B 做 DPO——**训练时以"提升学生正确率"为优化目标**，而非"说得像老师"。
- **EPFL 苏格拉底聊天机器人**（arXiv 2409.05511）：用专门数据对 Llama2 7B/13B 做微调+提示调优，局部可运行的**小模型**即可让"反思与批判性思维"显著优于普通聊天机器人。

## 四、墨衍教学引擎之可借鉴设计要点（18 条）

**A. 提问与"不给答案"（核心）**
1. **把"绝不直接给出答案"写成系统提示词的硬约束 + 替代动作清单**：直接借用 EduChat 引导式教学模板的五条原则（不给答案→问题拆解；针对性追问→按认知漏洞设计下一问；脚手架→具体→抽象、已知→未知；辩证批判→反例/悖论；元认知→"你如何验证？"）。同时给"学生直接要答案"时的替代话术（如 Khan 论文建议的"redirect 到解题方法"）。
2. **一次只问一个问题，问完必须停住等学生回答**：照抄 Ranedeer 的 `[IF tutor asks...] <stop your response> <wait for student response>`——实现为"导师输出到问号即打 stop 标记、前端停流"。
3. **用"关键词泄漏率"做自动化护栏**：在测试集上统计导师回复中是否提前泄露答案关键词/关键数字（HeuristicEdu 的 leakage 指标），作为每个模型/prompt 版本的发布门禁。
4. **学生反复答错 ≠ 故意的**：Khan 论文提醒——重复错误可能是"迷路了"而非"想要答案"，prompt 里要求导师先判断学生状态再决定不透露 vs 给保底提示。

**B. 判断对错与分支**
5. **判题双轨制**：数理/公式/数值/字符串题 → 确定性校验器（OATutor 的 Algebraic/String/Numeric 检查器，或代码执行）；开放题 → LLM 裁判 + 结构化 rubric，测评 prompt 可复用 Khan 公开的二分评估模板（"导师是否指出学生错了？yes/no"）。
6. **专门训练/评测"错误纠正"能力**：实证表明纠错是模型最弱项（Khan：68.5% vs 85.8%），墨衍应把"定位错误 + 纠正错误"做成独立评测任务（MathTutorBench 的 mistake_location / mistake_correction）。
7. **答错自动进入提示路径，但设保底**：OATutor 的 `giveHintOnIncorrect` + `giveStuBottomHint`——答错→自动给下一级提示（hint→scaffold→bottom-out），最后一次才给答案，避免学生卡死。
8. **防"学生糊弄"**：识别"学生直接要答案 / 反复追问答案 / 声称自己对了但明显错误"三类对抗行为（Khan 论文），prompt 给出应对策略，例如请学生先展示中间步骤再回应。

**C. 薄弱点记录与下一章决策**
9. **薄弱点落到知识点粒度（skill-level），用概率掌握度**：借鉴 BKT 四参数（mastery/transit/slip/guess），PostgreSQL 存 `skill_mastery` 表（按学生对知识点的 P(correct) 更新），而不是只记"这道题错了"。
10. **下一题/下一讲由"最低掌握度优先"驱动**：OATutor 的选题启发式、OpenTutor 的 LOOM 前置关系（先修概念未掌握不教后继概念）——墨衍的"从第 X 章开始"应改写为"从缺口知识点开始"。
11. **记忆要可审计、可人工修正**：仿 DeepTutor L1 事件流（每次问答/对错/耗时 append-only JSONL 或 PG 事件表）+ L2 掌握度快照（MD/表），薄弱点结论必须能回溯到具体答错事件——这也是给用户"我哪里弱、为什么"解释的来源。
12. **掌握门槛（mastery gate）**：每章末尾测验达到阈值（如 P(correct)>0.85 或连续 N 题正确）才解锁下一章；用"新题/变式题"而非原题判定（LearnLM RCT 用 novel problems 测迁移）。

**D. 讲解与出题策略**
13. **测验三级难度 + 先示例后考**：Ranedeer 的 3/10 熟悉简单 → 6/10 熟悉复杂 → 9/10 陌生复杂；先讲一道带逐步解答的示例题、确认看懂再开考。
14. **每次讲解都带教材引用**：OpenTutor/DeepTutor 的 citation 机制（句子级来源标注）——既防幻觉又让"分章节"的电子教材成为可点击的知识地图。
15. **用行为信号动态调难度**：OpenTutor 的认知负荷信号（疲劳、错误模式、消息长度、重复错误）→ 决定"深入讲解 / 跳过 / 放慢 / 给更多脚手架"，而不是固定节奏。
16. **情绪与动机是教学的一部分**：表扬-纠错节奏要平衡（Tutor CoPilot 分类器里 "effective praise" 是高质量策略之一）；识别挫败信号时切换到 EduChat 式情感支持/鼓励话术。

**E. 工程与评测**
17. **统一 OpenAI 兼容 Provider 层 + 熔断路由**：DeepTutor/OpenTutor/ChatTutor/Bloom 全部走任一 OpenAI 兼容端点；墨衍的 GPT/Claude/DeepSeek 切换应抽象为 provider 层，并支持 vLLM/本地模型接入成本地降级。
18. **建自己的"导师能力评测集"并做模型回归门禁**：按 MathTutorBench 7 任务（解题/苏格拉底提问/判定学生解法/定位错误/纠正错误/脚手架/原则遵循）建 30-100 题中文评测集，每次改 prompt、换模型、调温度都跑分，用"苏格拉底提问分 + 泄漏率 + 纠错准确率"决定默认模型。
